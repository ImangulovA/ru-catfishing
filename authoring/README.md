# Ручная сборка дней

Автоматический пайплайн (`compose_days.py` + `REALIA_PIPELINE.md`) выдохся на
дне 155 (6 ноября 2026): из 1751 отскринённой темы 1610 уже разошлись по дням,
на новый день не набирается даже десятка. Дни **с 156** собираются руками.

Чтобы дожить до 31 декабря, нужен день **210** — это 55 дней, 550 загадок.

## Как это устроено

```
authoring/drafts.json          <- источник правды, человекочитаемый, под гитом
        |                          (заголовок, все категории, какие скрыты,
        |                           зачёты, сложность)
        |  scripts/build_from_drafts.py
        v
app/src/lib/days/day<N>.json   <- то, что уезжает в игру: категории, sha256
                                  зачётов, base64 заголовка
```

Разделение нужно ровно для одного: черновик можно править сколько угодно раз,
он остаётся текстом, который читает человек. Хеши и base64 появляются только на
последнем шаге и всегда пересчитываются заново.

`norm()` — функция, которая приводит ответ игрока к каноническому виду перед
хешированием, — живёт в трёх местах сразу (`scripts/make_day.py`,
`scripts/build_pool.py`, `app/src/routes/+page.svelte`) и должна совпадать байт
в байт. Поэтому редактор ничего не хеширует в браузере: вся работа с
категориями, псевдонимами и хешами идёт в Python и переиспользует те же
функции, что и автоматический пайплайн. Проверено на дне 155: собранная
редактором загадка совпадает с отгруженной машиной по категориям, зачётам и
`reveal` до байта.

## Работа

```bash
python3 scripts/author_server.py        # открыть http://127.0.0.1:8765
```

В браузере:

1. **Заголовок** — начни печатать, поиск по ru.wiki подскажет статью; выбери из
   списка или нажми «Подтянуть».
2. **Категории** подтягиваются сами. Служебные («по алфавиту»), выдающие ответ
   (содержат слово из заголовка) и содержащие заголовок целиком зачёркиваются
   автоматически — у них пунктирная рамка. **Клик по любой категории убирает
   или возвращает её.** Это и есть ручка «убрать слишком очевидное»: фильтр
   ловит «Коала» в «Коалы», но не поймает «Коаловые» — такие убираешь сам.
3. **Зачёты** собираются из редиректов Википедии, англовики и фамилии (для
   людей). Лишние удаляются крестиком, свои добавляются в поле «+ ещё зачёт».
4. **Сложность** — easy/medium/hard. В шапке счётчик: в дне должно быть
   3 easy / 4 medium / 3 hard и не больше 5 людей, как в машинных днях.
5. Всё сохраняется само в `drafts.json` (полсекунды после правки).
6. **«Собрать день»** — записывает `day<N>.json` и перегенерирует `index.js`.
   Кнопка не откажет молча: если день не готов, внизу появится список проблем.

День не соберётся, пока в нём не будет ровно 10 загадок, у каждой хотя бы
4 видимые категории, хотя бы один зачёт, выставленная сложность, и заголовок не
светится ни в одной из показанных категорий.

## Ограничения, поставленные намеренно

- `build_from_drafts.py` не трогает дни ниже `MANUAL_FROM = 156` — машинные дни
  из черновиков перезаписать нельзя.
- Сервер слушает только `127.0.0.1` и пишет ровно в два места:
  `authoring/drafts.json` и `app/src/lib/days/`.
- `compose_days.py` оставлен как есть. Если пул когда-нибудь расширят через
  `REALIA_PIPELINE.md`, автоматический путь снова заработает.

## Команды без браузера

```bash
python3 scripts/build_from_drafts.py --check      # что готово, что нет
python3 scripts/build_from_drafts.py --day 156    # собрать один день
python3 scripts/build_from_drafts.py              # собрать все готовые
```
